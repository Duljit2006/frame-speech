The Encoder-Decoder Cross-Attention Failure

Why standard monolithic transcription engines hallucinate on out-of-distribution code-switched phonemes.

Pure Whisper ASR

Models like Whisper rely on global language tokens. When a speaker switches languages mid-sentence, the attention heads collapse, causing the decoder to hallucinate or forcefully transliterate out-of-vocabulary words into the dominant script.

// Audio input: "In Hindi we say समय, too different!"

❌ Decoder output:
"In Hindi we say samay, too different!" (Loss of native script)
- OR -
"इन हिंदी वी से समय टू डिफरेंट" (Loss of Latin code-switch)

FrameSpeech Pipeline

We bypass global token reliance by isolating language domains via 0.5s temporal binning. We force targeted language hints per tensor slice, then reconstruct the semantic structure using LLM orthographic post-processing.

// Audio input: "In Hindi we say समय, too different!"

✅ FrameSpeech output:
"In Hindi we say समय, too different!"
(Perfect word-level bilingual boundary preservation)

7-Stage Tensor Pipeline

Detailed breakdown of audio processing algorithms and model parameters.

Stage 01

Audio Extractor

Uses yt-dlp and ffmpeg-python. Resamples input streams to 16kHz, downmixes to mono (ac=1), and forces PCM 16-bit little-endian (pcm_s16le) encoding to normalize mel-spectrogram generation.

Sample Rate: 16000Hz | Channels: 1
Stage 02

Silero VAD

Evaluates float32 audio tensors via a lightweight PyTorch neural VAD. Identifies active speech indices against a strict probability threshold to strip compute-heavy silence.

Confidence Threshold: ≥ 0.50
Stage 03

Segmentation

Generates sequential overlapping audio frames using a targeted sliding window algorithm to ensure boundary phonetic transitions are fully captured for the classifier.

Window: 3.0s | Stride: 1.0s | Overlap: 66%
Stage 04

SpeechBrain LID

Executes vectorized inference on 107-class ECAPA-TDNN embeddings. Applies an -inf log-softmax mask to filter out non-Indian language classes prior to activation.

Batch Size: 32 | Fallback Threshold: < 0.70
Stage 05

Timeline Smoother

Consolidates raw predictions via non-linear median filtering and confidence-weighted majority voting across 0.5s bins. Applies multi-pass glitch absorption for blocks under 2.5s.

Time Bin Resolution: 0.5s
Stage 06

faster-whisper

Executes CTranslate2 int8 quantized transcription. Disables internal redundant VAD. Applies gated language hinting and drops segments where alpha_count < length * 0.3.

Hint Gate: ≥ 0.85 | Quantization: int8
Stage 07

Gemini AI Corrector

Restructures textual fragments into complete sentences while enforcing zero-shot code-switching rules. Utilizes strict JSON schema parsing and dynamic exponential backoff on 429 errors.

Batch Size: 100 | Temp: 0.2 | format: JSON

Engineering & Optimizations

Interactive deep dive into how FrameSpeech achieves maximum efficiency on a 4GB RTX 2050 GPU.

Overcoming the 4GB Memory Wall

FrameSpeech runs multiple heavy neural networks. A 4GB RTX 2050 cannot hold SpeechBrain (~1.2GB) and Whisper large-v3 (~2.5GB) simultaneously. If both load, the system crashes with a CUDA Out Of Memory error.

The Solution: We implemented strict memory choreography in orchestrator.py. CTranslate2 objects cannot simply be moved to the CPU; they must be explicitly destroyed and the CUDA cache wiped completely before loading the next stage.

orchestrator.py

Memory Mgmt 
# 1. Destroy SpeechBrain Fallback Model
if self.lid.whisper_model:
    del self.lid.whisper_model
# 2. Hard clear the GPU Memory
torch.cuda.empty_cache()

# 3. Load heavy Whisper Transcriber safely
transcriber = TranscriptionProcessor(...)

Massive Compute Reduction

Running audio frame-by-frame takes hundreds of GFLOPs. We use three strategies to optimize throughput:

1. Vectorized Batching

Instead of inferencing 3-second chunks sequentially, we stack them into a single tensor block of 32 chunks. This utilizes the GPU's parallel cores, speeding up LID by 400%.

2. Zero-Compute VAD

The Silero VAD model runs exclusively on the CPU. It strips out all silence before any heavy AI models touch the audio, saving thousands of GPU cycles.

3. Lazy Loading Fallback

SpeechBrain detects 90% of speech accurately. We only initialize the secondary fallback language model if SpeechBrain's confidence drops below 70%, keeping VRAM free.

Solving the Assamese Orthography Issue

OpenAI's Whisper model does not officially support Assamese. It frequently hallucinates Bengali characters due to the languages sharing a similar script.

We developed a "Hack" to bypass this: We intentionally hint the Bengali model, and then use a rigid LLM Post-Processing prompt in Gemini to structurally convert Bengali orthography (র, ব) to Assamese orthography (ৰ, ৱ) while preserving the phonetic transcription exactly.

Raw Whisper Output:
আমি অসমীয়া কওঁ। (Bengali script hallucination)
After Gemini Correction:
আমি অসমীয়া কওঁ। -> আমি অসমীয়া কওঁ। (Corrected characters)
ৰ, ৱ applied.
{"text": "আমি অসমীয়া কওঁ।", "language": "as", "error_flag": false}

Zero-Hallucination Code Switching

When speakers mix English and Hindi (Hinglish), standard AI models force everything into a single language output, producing garbage text. By passing the exact --language flag dynamically for every chunk based on our prior SpeechBrain timeline, we force Whisper to respect the phonetic boundaries perfectly.
